
# A Beginner’s Guide to Using GitHub
## Introduction
GitHub is like cloud storage where you store, edit, and deploy your code. A simpler way to think of it: imagine Google Drive, but instead of just storing documents, it also keeps a full history of every change ever made to those documents, and lets a whole team edit, review, and build on top of each other's work without overwriting one another.

That's what makes GitHub more than just storage — it's a workspace. It doesn't only help you keep and manage your code; it allows you to collaborate with other people involved in a project, such as developers, technical writers, and project managers. It's a multipurpose platform that supports the whole lifecycle of building software, from writing the first line of code to deploying the finished product.

## Git vs GitHub

To avoid confusion, let's briefly differentiate the two.

Git is a software application installed on your computer that saves and tracks the history of changes to your code, locally. Think of it like a CCTV camera — but instead of recording a room, it records your code: what changed, and when. Because Git runs locally, collaboration is actually possible with Git alone, without GitHub. Developers can send updates directly to each other over a local network, share code patches via email, or set up their own private servers to host Git repositories as a team.

GitHub, on the other hand, is a cloud platform built on top of Git for storing and sharing that code online. If Git is the camera recording locally, GitHub is the cloud where that footage gets uploaded so others can view and work with it. This is why most teams prefer GitHub over using Git alone — it adds a visual layer that makes teamwork easier. It gives everyone a central hub to push and pull updates from, introduces Pull Requests so teammates can review and comment on code before it's merged, and includes built-in project management tools for tracking bugs, tasks, and team discussions.
